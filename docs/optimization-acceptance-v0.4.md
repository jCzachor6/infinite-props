# v0.4 compiler and file optimization acceptance

Verified on 2026-10-03 through D.2, against the reference lowering retained
by `ipc --no-opt`. The corpus contains 56 tracked `.ips` sources, including
parts, the 24 recipes and all v0.4 language fixtures.

| Artifact mode | Reference total | Optimized total | Reduction |
| --- | ---: | ---: | ---: |
| With debug | 151,484 bytes | 137,485 bytes | 9.24% |
| Stripped | 84,544 bytes | 77,505 bytes | 8.33% |

Each artifact fits its own reference size in both modes. Five seeds per mode
produce 530 pixel-identical image/bit-identical structured-output comparisons
and 30 matching runtime failures. Fuel cost and relocated byte offsets are
excluded from semantic equality. This check is registered in CTest when
Python is available and can be rerun directly:

```sh
python3 scripts/check-optimizations.py build/tools --report /tmp/optimizations.json
```

The pre-optimization v0.4 corpus was also rendered separately; all 56 sources
retain its images, raw outputs and trap reasons. The frozen v0.1–v0.3 binary,
image and specification pins remain unchanged. CTest passes all nine suites,
including C, SFML, Godot and editor checks. Native/WASM checks
pass seven frozen entries, 276 rendered images/structured outputs, 19 runtime
traps, 6,292 vector boundary results and 29 RGBA boundary results.

The core suite passes 338,354 assertions in 430 cases with AddressSanitizer,
UndefinedBehaviorSanitizer and float-cast-overflow checks. macOS does not
support LeakSanitizer in this environment, so leak detection was disabled.
A separate 65,536-element color palette reaches the u16 pool limit: optimized
and reference artifacts remain 2,621,628 bytes each and render the same highest
variant. This verifies fallback when a color fold would need another pool
entry.

The figures describe compiler IR optimization without container compression.
The checker selects unpacked output when that option is available; format
compression is verified separately.

## File compression and production defaults

Lossless v0.4 zlib/DEFLATE envelopes contain the complete original file.
Packing occurs only when the envelope is smaller. The CLI strips debug
data before packing by default; `--debug` retains maps and symbols and
`--no-compress` selects expanded output. The compiler API retains debug data.

| Final artifact mode | Pre-optimization baseline | Optimized and packed | Reduction |
| --- | ---: | ---: | ---: |
| With explicit debug | 151,484 bytes | 31,742 bytes | 79.05% |
| Default production | 84,544 bytes | 27,302 bytes | 67.71% |

Every file fits its own baseline, including its container header. Independent
zlib decoding reproduces each optimized expanded artifact byte for byte;
default output equals explicit `--strip` for all 56 sources. Five seeds per
source retain all 265 successful pre-optimization images/raw outputs and 15
runtime trap reasons. All 18 frozen binary/image/assembly/specification files
retain their original hashes.

Native/WASM compression checks retain seven historical images and reject
12 malformed envelopes consistently. Native loader tests additionally cover
dictionary streams, nesting, resource caps and historical opcode version
gates. The full backend counts above also pass with default packed production
files generated by the current CLI.

The editor command integration test uses the real compiler/disassembler/
validator with a VS Code API facade: the inspector retains source maps and
binary export equals the stripped CLI default. It passes with both build-tree
and installed tools. A relocated SDK passes all six CLI tools, shared/static
C consumers and the installed SFML export, including explicit debug maps.
