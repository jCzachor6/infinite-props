FAQ

Is the output really deterministic?

Yes, bit-exactly. Generation is a pure function of the inputs — the seed, the variant/archetype indices, the requested size and the uniform values. The seeded primitives (hash, stream draws, noise) are specification-pinned algorithms, and a golden corpus of committed images guards the pipeline: any change that alters a golden pixel is a breaking change.

What are seed, variant and archetype?

  • seed — the root of every random stream; the same seed always reproduces the same asset.
  • archetype — the coarse form (an asset declares archetypes N; think "boulder vs slab").
  • variant — the finer variation within an archetype (variants N).

Both indices are the read-only v/a builtins in the draw { ... } entry block, so an asset author decides exactly how they shape the output.

Why a bytecode VM instead of shipping the code?

Bytecode is small, self-contained, portable and safe: hosts validate a binary before executing it, the instruction set pins every operation, and a fuel budget guarantees termination. The same binary runs on every backend — the browser, the tools, the future native hosts — with identical pixels.

How do composed assets work?

An asset can import other assets as parts (import hair from "hair.ips"). The compiler links them into one self-contained binary; the parent calls part.draw(seed, v, a, at = {x, y}, uniforms…) — call order is paint order — and reads the part's structured outputs through part.outputs.name.

How do I contribute?

The repository is organised by layer: the frozen format spec (spec/), the runtime, the language and the compiler, the backends, the editor and this website. Every change runs the desktop test suite and the golden corpus, and semantic changes require a spec update first.
