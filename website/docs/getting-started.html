iprop

Getting started

iprop is a portable binary format and toolchain for seed-based procedural 2D assets: you author an asset in the .ips language, compile it to a self-contained .iprop binary, and any backend renders it — deterministically — from a seed.

Install the toolchain

The toolchain is C++20 with CMake and zlib ≥ 1.2.9 (Linux: zlib1g-dev; macOS: platform SDK; Windows: vcpkg). Clone and build:

git clone <repository-url> iprop
cd iprop
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel

This produces the tools under build/tools/:

toolwhat it does
ipaassemble .ipa → .iprop
ipccompile .ips → .iprop
ipgenrender a .iprop to a PNG + result JSON
ipsheetrender a variant × seed grid
ipdisdisassemble a binary (optionally with source lines)
ipvalvalidate a binary

Your first asset

Write rock.ips:

asset rock {
  size 192x192
  origin 96,170
  variants 5
  archetypes 4
  input  color palette = #808d74
  output rect  collider

  draw {
    w = range(21, 31)
    h = range(35, 49)
    collider = {96 - 20, 170 - 23, 40, 23}
    rect(-w * 0.10, 0, w * 0.87, h, palette)
    if (index(3) == 0) {
      rect(-w * 0.67, 2, w * 0.39, h * 0.43,
           color.shade(palette, -4))
    }
  }
}

Compile it, then render a seed:

./build/tools/ipc rock.ips -o rock.iprop
./build/tools/ipgen rock.iprop --seed 7 -o rock.png

The compiler writes stripped production files and compresses only when smaller. Add --debug for source maps and symbols, or --no-compress for expanded inspection.

ipgen prints the result JSON (the structured outputs and the fuel readout). The same seed always renders the same pixels — on every platform and backend.

The editor

For an authoring experience, use the VS Code extension (editor/ in the repository):

cd editor
sh install.sh

Reload VS Code and open any .ips file: syntax highlighting, inline diagnostics from the compiler, a live preview with seed controls, an atlas browser, a bytecode inspector and one-click exports. The integrated terminal is your console for CLI agents (opencode, codex) — they edit the files and the extension recompiles.

The compiled tools are expected at <workspace>/build/tools; every tool accepts a -h/--help flag with the exact options.
