Backends and installation

All backends execute the same validated bytecode; the reference CPU interpreter is authoritative for correctness, and the conformance suite checks every backend against the golden corpus.

The CLI toolchain

cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel

Tools under build/tools/: ipc (compile), ipgen (render), ipsheet (grids), ipdis (disassemble), ipval (validate), ipa (assemble). Each prints --help.

HTML5 / WASM

The reference interpreter compiled to WebAssembly — powers this playground and the IDE preview. Requires Emscripten.

mkdir -p build/wasm && cd build/wasm
emcmake cmake ../../backends/html5 -DCMAKE_BUILD_TYPE=Release
emmake make -j4
cd ../.. && backends/html5/prepare.sh

The demo page (backends/html5/demo/) renders example sheets; the conformance suite (node backends/html5/test/run-tests.js build/wasm) checks the golden seeds. Details in backends/html5/README.md.

VS Code

cd editor
sh install.sh

Reload VS Code: syntax highlighting, compiler diagnostics, the live preview with seed controls, the atlas, the bytecode inspector and exports. The integrated terminal is the console for CLI agents.

C API, SFML and Godot

The native integrations are implemented in 0.2. The C99 interface (backends/capi/iprop.h) ships shared and static libraries, with owned program/result handles, RGBA pixels and structured output owners.

cmake -B build -DCMAKE_BUILD_TYPE=Release \
  -DIPROP_SFML=ON -DIPROP_SFML_PREFIX=/path/to/sfml \
  -DIPROP_GODOT=ON -DIPROP_GODOTCPP_DIR=/path/to/godot-cpp \
  -DIPROP_GODOT_BINARY=/path/to/godot
cmake --build build --parallel
ctest --test-dir build --output-on-failure

SFML 3.1 provides the desktop sprite/atlas host, PNG exports and actual sprite render tests. Its source build requires CMake 3.28 or later. Godot 4.5.2 with godot-cpp at godot-4.5-stable provides IpropAsset and IpropSprite2D; the generated demo project is under build/godot-project/. Output names remain separate between the root and each part.

IPROP_SFML/IPROP_GODOT accept AUTO (skip missing dependencies), ON (require them) or OFF. See the backend READMEs for exact library, export and ownership contracts. OpenGL, Vulkan, Bevy and Unity integrations remain future work.
