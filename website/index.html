Infinite Props is a portable binary format, an open runtime and a toolchain for seed-based procedural 2D assets. You describe a prop once in the small .ips language, compile it to a self-contained .iprop file, and a tiny sandboxed virtual machine turns any seed into pixels, bit for bit the same in the browser, in your engine and on every operating system.

One file is not one image. It is a recipe for endless variations, and every result comes with the data your game needs: colliders, anchor points and colours.

Build procedural game sprites for Unity, Apple, Android and Python, Godot and SFML, or the web with WebAssembly. Generate trees, weapons, portraits and scenery from reusable recipes, with seeds and inputs controlling each variation.

Each wing part generates one side, then the browser mirrors it. The body sits on top. Wings flap independently around the body as every new butterfly takes flight. Each seed draws a fresh combination of shapes, colours and patterns from the same three files. The body takes its proportions and colour cues from the wings, so the parts fit together. Mirroring reuses the generated wing images, keeping both the download and the amount of generation work small. The simplest example

One program, a whole top‑down forest

A program does not describe one picture. It describes a kind of thing, and a seed picks one. This tree is three small files: tree.ips lays rings of leaf clumps from the rim to the top, clump.ips, a part of its own, draws one clump lit from the upper left in a five-tone ramp, over its own shadow, and foliage.ips is the leaf material both share: a colour and the shadow, light and rim that follow it. Leaves draw from seven colour ranges: deep, olive, lime and blue-green most of the time, now and then autumn reds, oranges and golds.

import clump from "clump.ips"
import foliage from "foliage.ips"
// A tree from above: rings of leaf clumps, the rim first and the
// top last.
asset Tree {
  size 176x176
  origin 88,88

  draw {
    R = 34.0 to 58.0 with gaussian(mean=46.0, sigma=5.0)
    leaf = foliage.Leaf()
    for ring in 0..3 {
      n = max(1, (6 to 8) - ring * 3)
      turn = 0.0 to 6.2832
      for i in 0..n {
        a = turn + float(i) * 6.2832 / float(n)
        a = a + (-0.25 to 0.25)
        d = R * (0.6 - float(ring) * 0.3) * (0.8 to 1.15)
        r = R * (0.44 - float(ring) * 0.06) * (0.8 to 1.15)
        clump.draw(hash(seed ^ (ring * 16 + i)),
                   at={88.0 + cos(a) * d, 88.0 + sin(a) * d},
                   r=r, lift=-(cos(a) + sin(a)) * 0.2 * d / R,
                   leaf=color.shade(leaf.base, -8 to 8))
      }
    }
  }
}
import foliage from "foliage.ips"
// One clump of leaves from above, lit from the upper left: lobes
// and leaves in a five-tone ramp, over their own shadow.
asset Clump {
  size 64x64
  origin 32,32
  input f32 r = 12.0
  input f32 lift = 0.0
  input color leaf = #4a8a3a

  draw {
    // A part takes colours, not materials: the leaf material is made
    // here from the colour the tree passes in.
    m = foliage.Leaf(base = leaf)
    // Five tones from the shadow to the light.
    tones = stepper(m.shadow to m.light).pick(5)
    layer lobes(alpha=surface.source_over) {
      body = r * 0.72
      oval(32.0, 32.0, body, body, tone(tones, 0.3 + lift))
      for i in 0..9 {
        a = float(i) * 0.7 + (-0.3 to 0.3)
        x = 32.0 + cos(a) * r * 0.66
        y = 32.0 + sin(a) * r * 0.66
        lr = r * (0.28 to 0.4)
        lit = lift + 0.35 - (x + y - 64.0) / r * 0.1
        oval(x, y, lr, lr, tone(tones, lit))
      }
      for i in 0..int(r * r * 0.2) {
        a = 0.0 to 6.2832
        d = sqrt(0.0 to 1.0) * r * 0.85
        x = 32.0 + cos(a) * d
        y = 32.0 + sin(a) * d
        lit = lift + 0.4 - (x + y - 64.0) / r * 0.4
        s = 0.8 to 1.8
        j = -0.25 to 0.25
        oval(x, y, s, s * 0.8, tone(tones, lit + j))
      }
    }
    surface.paint(mask.offset(mask.from(lobes), 1, 2), m.rim)
    surface.paint(lobes)
  }

  // The nearest of the five tones.
  tone(tones: list<color>, t: f32) -> color {
    return tones[int(clamp(t, 0.0, 1.0) * 4.0 + 0.5)]
  }
}
// The look of a tree's leaves: a colour and the shades that follow
// it, so any colour keeps a matching shadow, light and rim.
// Mostly greens (deep, olive, lime, blue-green), now and then
// autumn reds, oranges and golds.
palette greens = [#1f5a3a to #3f8a4c, #4a6a24 to #8aa03a,
                  #5a9a2a to #a8c840, #2a6a6a to #5a9a7a,
                  #8a2a24 to #c8402a, #c0581e to #e8902a,
                  #c89a20 to #f0d050]
const distribution kinds = weighted {0: 22, 1: 18, 2: 18,
  3: 14, 4: 9, 5: 10, 6: 9}

material Leaf {
  // Each tree takes its own turn on its range: a touch of hue,
  // more or less saturated.
  base = color.hsv(greens[0 to 6 with kinds].pick(),
                   -0.015 to 0.015, 0.9 to 1.15, 1.0)
  // A cool shadow and a warm light, lit from the upper left; both
  // stay saturated, so the ramp between them never turns grey.
  shadow = color.hsv(color.mix(base, #0c2238, 0.55), 0.0, 1.2, 1.0)
  light = color.hsv(color.mix(base, #fff6b0, 0.4), 0.0, 1.15, 1.05)
  rim = color.hsv(color.mix(base, #040a14, 0.8), 0.0, 1.3, 1.0)
}

Main features

Bit-exact determinism

The same seed renders the same pixels and outputs on every platform and backend. A committed golden corpus guards every release.

One file, endless props

An .iprop file is a recipe, not an image. Seed and authored inputs unlock a practically unlimited, reproducible family of sprites.

Safe to run anywhere

Validated bytecode, structured control flow only and a hard fuel budget: even an untrusted file cannot hang or escape its host.

A language for pixels

.ips speaks sprites: palettes, rects, distance helpers, lo to hi ranges and colour gradients, compiled with precise diagnostics.

Shaped randomness

Gaussian, triangular and beta distributions steer every roll, so proportions look designed rather than noisy.

Composable parts

Import a blade, a hilt, a face. Parts link into one self-contained binary, paint in call order and report outputs in the caller's coordinates.

Structured outputs

Colliders, anchors and colours come back with the pixels: the tip of a sword, the eyes of a portrait, the colour of a hat.

Tiny binaries

Each weapon pack on this page compiles to 7 to 11 KB. Files are zlib-packed whenever that is smaller and never need external resources.

Runs everywhere

One reference interpreter for Linux, macOS, Windows and WebAssembly. The tiles above are running it in this page.

C API and engines

A C99 interface on a versioned ABI (C API {{C_API_VERSION}}, SONAME {{C_ABI_SOVERSION}}), with SFML and Godot GDExtension integrations built on top.

Authoring toolchain

ipc, ipgen, ipsheet, ipdis, ipval and a VS Code extension with live preview, atlas and bytecode inspector.

Ready for coding agents

A compact, machine-checked LLM reference ships with every release, so an agent can write props in .ips alongside you.
